# Testing (for agents)

One test project: `src/PharmacyDelivery.Tests` (solution `src/PharmacyDelivery.Tests.slnx`). NUnit 4 + Moq + NetArchTest + Testcontainers. Test plan with
numbered cases: `docs/test-plan.md` (generated by `scripts/generate-test-plan.py`).

```bash
dotnet test src/PharmacyDelivery.Tests.slnx --filter "TestCategory!=Integration"   # no Docker, seconds
dotnet test src/PharmacyDelivery.Tests.slnx --filter "TestCategory=Integration"    # Docker required
dotnet test src/PharmacyDelivery.Tests.slnx --filter "FullyQualifiedName~CheckoutServiceTests"
```

## Layout

| Folder | What | Base class |
|---|---|---|
| `Common/`, `Domain/`, `Services/`, `Infrastructure/`, `Messaging/` | unit tests | `TestBase` |
| `Architecture/` | layering, DI in one file, audit attributes, folder layout, docs ↔ code (configuration, test plan, interface docs) | `TestBase` |
| `Integration/` | API host + PostgreSQL/PostGIS, Redis, RabbitMQ in containers | `IntegrationTestBase` |
| `Seed/` | test data templates (`minimal`, `concurrency`, `reassign`, `dispatch`), `TestWorld` ids/accounts, `[UseSeed]` | — |
| `Support/` | `FixedClock`, `InlineUnitOfWork`, `TestLog`, `RepositoryPaths` | — |

One fixture per file. Name: `Method_Scenario_Expected`. Every test: `[Property("TestCase", "TC-7.M.K")]`.

## TestBase (unit)

Each test gets a fresh DI container:

```csharp
[TestFixture]
public sealed class PaymentServiceTests : TestBase
{
    private PaymentService _service = null!;

    private Mock<IPaymentGateway> Gateway => MockOf<IPaymentGateway>();

    [SetUp]
    public void SetUp()
    {
        Settings["Payments:WebhookSecret"] = "secret";            // bound to PaymentsOptions like in production
        _service = Service<PaymentService>();                      // builds the class; missing interfaces become mocks
        MockOf<IOrderRepository>().Setup(o => o.GetForUpdateAsync(…)).ReturnsAsync(…);
    }

    [Test]
    [Property("TestCase", "TC-7.5.5")]
    public async Task PaymentAfterReservationExpired_IsRefunded()
    {
        Assert.That(await _service.HandleWebhookAsync(…, Ct), Is.EqualTo("refund"));
        Gateway.Verify(g => g.RefundAsync("fake_1", It.IsAny<Money>(), It.IsAny<CancellationToken>()), Times.Once);
    }
}
```

- Order: `Settings` / `Services.Add…` / `MockOf<T>()` **before** `Service<T>()`/`Get<T>()` (that builds the container); setups and verifies after.
- Real implementations: register them in `Services` (e.g. `Services.AddSingleton<IPasswordHasher<User>>(hasher)`); concrete `PharmacyDelivery.*`
  dependencies are built automatically.
- Provided: `Now` (fixed 2026-10-21 10:00 UTC), `Clock` (`Clock.Advance(…)`), `UnitOfWork` (counts saves), `Logs.Entries`, `Ct`,
  `OptionsValue<T>()`; for code built by hand `OptionsOf(…)`, `ClockAt(…)`.

## IntegrationTestBase

- Containers start once per run (`IntegrationEnvironment`), API host via `WebApplicationFactory` in environment `IntegrationTests`
  (background jobs off, high rate limits).
- Data: `[UseSeed(TestSeedProfiles.Minimal)]` on the fixture (method-level overrides) — TRUNCATE + seed before each test, same code path
  as `Seed:Mode=Reset`. New template: class implementing `ISeeder` with `[SeedProfile(TestSeedProfiles.X, Order = n)]` in `Seed/`,
  plus a constant in `TestSeedProfiles` and a line in `docs/test-plan.md` §5.
- Helpers: `LoginAsync(TestWorld.Customer)`, `Anonymous()`, `customer.CheckoutAsync(...)`, `PaidOrderAsync`, `AcceptAndPackAsync`,
  `WaitForStatusAsync` (asynchronous steps go through RabbitMQ — never `Task.Delay`), `ExecuteSqlAsync`, `Get<T>()` from a host scope.
- `[NonParallelizable]`; needs ~2 GB for Docker — stop the compose stand first on small machines.

## Test plan

Add a case: append it to its area in `SPEC` of `scripts/generate-test-plan.py` (never renumber; removed cases stay with automation
`retired`), run the script, put the `TC-` id on the test. `DocumentationTests.TestPlan_NumberingIsContinuous_AndMatchesAutomatedTests`
fails on gaps, missing tests or unknown ids.

## In the Docker build

The API Dockerfile `test` stage runs the non-integration tests and stores `junit.xml`, `tests.trx`, `coverage.cobertura.xml` (coverage
scope: `src/PharmacyDelivery.Tests/coverage.runsettings`); `--target test-results --output type=local,dest=test-results` exports them; GitLab shows
them via `.gitlab-ci.yml`; GitHub Actions (`.github/workflows/ci.yml`) uploads them as artifacts and writes a job summary
(`scripts/junit-summary.py`). A failed test stops the image build after the report is written.
